# 业务上下文模板

最近刷新：`YYYY-MM-DD`

用途：

- 这是某个飞书项目空间的本地业务上下文文件模板
- 目标是把“业务规则 + 字段映射 + 角色映射 + 缓存候选值”沉淀下来
- agent 先读这份文件，再决定是否 live query
- live query 命中新值后，要回写这份文件

建议：每个空间单独维护一份，不要把多个无关空间混在同一份文件里。

## 适用范围

- 空间 `project_key`: `TODO_PROJECT_KEY`
- 空间 `simple_name`: `TODO_SIMPLE_NAME`
- 默认工作项类型：`story`

如果用户目标不是这个空间，或本文件无法命中，再回退到 MCP 查询。

## 使用规则

1. 本地缓存候选值优先展示给用户。
2. 本文件里的任何值都只能作为建议，不能静默写入。
3. 用户没确认时，不要创建或更新。
4. 用户说“没有我要的”“查最新”“列完整列表”时，再做 live query。
5. live query 命中新值后，更新本文件对应区块。
6. 默认建议值只能作为预填候选值，必须在确认环节明确带给用户。
7. 可选链接字段、附件字段、备注字段，如果用户没明确给值，通常默认留空。

## 确认规则

### 总规则

- 任何准备写入的字段，只要不是用户本轮明确提供或明确认可，都视为未确认
- 目标迭代、主负责人、协作负责人、所属组件通常要显式确认
- 如果用户只说“负责人是某某”，不要自动同时填多个角色
- 第一次确认默认值时，先只带默认值；只有用户明确要改时，才展开候选项

### 某业务的必问项

这些字段缺失时必须先问：

- `field_xxxxx3` `所属组件`

- `role_owners` 里的 `主负责人`
- `role_owners` 里的 `协作负责人`

## 维护建议

- 新增候选值时，优先追加到对应字段区块
- 候选值失效或改名时，直接修正原行
- 如果某些值只适用于一个业务别名，单独写备注，避免被误复用
- 如果空间改模板、改字段、改角色，优先更新字段注册表和角色缓存
